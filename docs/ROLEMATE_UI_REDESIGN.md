# RoleMate MiniApp: финальная дизайн-система и аудит экранов

Дата фиксации: 5 августа 2026 года.

## Цель

Сохранить все существующие сценарии RoleMate, но сделать интерфейс предсказуемым для человека, привыкшего к Telegram и Instagram: один главный объект на экран, явная иерархия действий, компактная нижняя навигация, контекстные меню вместо нагромождения кнопок, жесты только как ускорение доступных кнопочных действий.

## Изученные первичные источники

- [Telegram Mini Apps](https://core.telegram.org/bots/webapps): динамические цвета Telegram, safe area, стабильная высота viewport, системные Back/Main buttons, mobile-first, доступные подписи и плавность интерфейса.
- [Instagram mobile navigation](https://about.fb.com/news/2025/09/in-india-instagram-debuts-a-reels-first-experience-for-its-mobile-app/): упрощённая навигация, центральный контент, быстрые переходы свайпом между соседними разделами.
- [Instagram messaging on desktop](https://engineering.fb.com/2022/07/26/web/launching-instagram-messaging-on-desktop/): адаптация мобильной модели к desktop, присутствие, галерея, drag-and-drop и разделение view/model.
- [Instagram performance and Baseline Profiles](https://engineering.fb.com/2025/10/01/android/accelerating-our-android-apps-with-baseline-profiles/): скорость первого запуска и переходов является частью качества интерфейса.
- [Instagram CSS at scale](https://engineering.fb.com/2026/01/12/web/css-at-scale-with-stylex/): единые атомарные токены и предотвращение расхождения локальных стилей.

Выводы ниже — адаптация этих принципов под RoleMate, а не копирование чужого интерфейса.

## Трёхслойная система токенов

### 1. Примитивы

- пространство: `4 / 8 / 12 / 16 / 20 / 24 / 32` px;
- радиусы: `10 / 14 / 18 / 24 / full`;
- типографика: `Inter` для интерфейса, `Cormorant Garamond` только для крупных эмоциональных заголовков;
- минимальная зона касания: `44 × 44` px;
- переходы: `140 / 220 / 320` ms, без пружин для критических действий;
- ширина контента: `680px` для лент, `980px` для редакторов и админки.

### 2. Семантика

- `canvas`, `surface`, `surface-raised`, `surface-glass`;
- `text-primary`, `text-secondary`, `text-tertiary`;
- `action-primary`, `action-secondary`, `action-danger`;
- `border-subtle`, `border-emphasis`;
- `shadow-card`, `shadow-overlay`, `blur-glass`;
- `safe-top`, `safe-bottom`, `content-safe-*`.

### 3. Компоненты

- `app-shell`, `topbar`, `bottom-nav`;
- `section-title`, `glass-card`, `button`, `icon-button`;
- `feed-card`, `profile-card`, `questionnaire-card`, `post-card`;
- `telegram-conversation`, `message-bubble`, `media-carousel`, `playlist`;
- `modal`, `popover`, `toast`, `empty-state`, `skeleton`.

Компонентные токены используют только семантические значения. Отдельные страницы не должны вводить несогласованные цвета фона или размеры кнопок.

## Общие правила взаимодействия

1. Кнопка остаётся доступна без жеста; свайп, удержание и двойной тап лишь ускоряют действие.
2. Любое destructive-действие открывает стилизованное подтверждение.
3. Верхнее меню раздела всегда центрируется относительно заголовка, имеет контраст в светлой и тёмной теме и не меняет положение при загрузке данных.
4. Медиа открывается тапом по самому медиа; лишние стрелки открытия не показываются.
5. Карусель листается свайпом, но имеет доступные кнопки навигации в полноэкранном режиме.
6. Нижняя навигация содержит шесть стабильных разделов; поиск является центральным акцентным действием.
7. Telegram safe-area и `viewportStableHeight` обязательны для шапки, чата, composer и нижней навигации.
8. `prefers-reduced-motion` отключает декоративные перемещения, сохраняя смену состояния.
9. Focus-visible, подписи `aria-*`, контраст и логический порядок DOM обязательны.

## Аудит текущего состояния

### Сильные стороны, которые сохраняются

- единый React/TypeScript стек и общие компоненты;
- Telegram safe-area, светлая/тёмная темы, центральный поиск;
- медиакарусели, fullscreen, плейлисты и глобальный музыкальный контекст;
- доступные кнопочные альтернативы жестам;
- полноценные regression E2E на трёх профилях устройств.

### Риски, которые устраняются финальным слоем

- смешение локальных фиксированных цветов с семантическими токенами;
- чрезмерное использование одинаковых крупных стеклянных карточек;
- неодинаковая плотность лент, редакторов и админки;
- локальные overrides светлой темы вместо системной семантики;
- слишком большой основной JS chunk и отсутствие route-level splitting;
- дублирующиеся CSS-правила, накопленные последовательными хотфиксами.

## Критерии приёмки

- все страницы из таблицы визуально используют одну систему токенов;
- нет горизонтального переполнения при ширине `320px`;
- светлая и тёмная темы читаемы на всех основных маршрутах;
- chat header, composer и нижняя навигация не перекрываются глобальным плеером;
- все существующие unit/integration/migration тесты проходят;
- полный Playwright проходит на Android, iPhone и desktop;
- production build, secret scan и dependency audit проходят;
- перед production есть verified backup и preview-миграция.
